## Часть 1. Структурный анализ

### definition
Ключевая структура в OVAL файле. Назначение `definition` меняется в соответствии со значением его атрибутом `class`:

| Class         | Назначение Definition                         |
|---------------|-----------------------------------------------|
| compliance    | соответствует ли машина определенной политике |
| inventory     | установлен ли заданный софт на машине         |
| patch         | нужно ли установить указанный патч на машину  |
| vulnerability | присутствует ли на машине заданная уязвимость |
| miscellaneous | назначение не подпадает под прочие категории  |

Каждый не-деприцированный definition (`deprecated=false`) содержит в себе один элемент `criteria`, 
используемый сканером для оценки соответствия. 

`criteria` представляет собой контейнер, содержащий набор проверок и других `criteria`, 
и задающий атрибут `operator` - логический оператор, определяющий действия над дочерними элементами.
Возможные значения `operator`: `AND, OR, XOR, ONE`

Каждая проверка задается с помощью элемента `criterion`, фактически выполняющего роль ссылки на тест,
заданный посредствам атрибута `test_ref`

Также `definition` всегда содержит элемент `metadata`. Он предназначен 
для чтения человеком и не используется для оценки состояния машины.

### objects
Представляет собой список объектов.

Объект задает условия сбора элементов с целевой машины для последующей проверки.

Набор условий, целевых элементов и полей обьекта зависят от его класса. 
Например, `rpminfo_object` собирает rpm-пакет по заданному `name`.
В то время как `textfilecontent54_object` парсит содержимое указанного в `filepath` файла 
с помощью регулярки из `pattern`, отдавая номер вхождения, заданный в `instance` 

<details>
<summary>Пример object</summary>

```xml
<ind-def:textfilecontent54_object id="oval:com.redhat.rhsa:obj:20203669014" version="641">
 <ind-def:filepath datatype="string">/etc/dnf/modules.d/postgresql.module</ind-def:filepath>
 <ind-def:pattern operation="pattern match">\[postgresql\][\w\W]*</ind-def:pattern>
 <ind-def:instance datatype="int">1</ind-def:instance>
</ind-def:textfilecontent54_object>
```
</details>

### states
Представляет собой список состояний.

Состояние описывает набор условий, которым должен соответствовать объект (элемент, возвращаемый объектом).
Каждое состояние должно задавать минимум одну проверку объекта, максимальное число не ограничено.
Атрибут `operator` задает логическое условие для связи проверок; по умолчанию `AND` - все проверки должны быть успешными.

Также как у объектов, возможные атрибуты и дочерние элементы состояния зависят от их класса.

<details>
<summary>Пример state</summary>

```xml
<red-def:rpminfo_state id="oval:com.redhat.rhba:ste:20192715003" version="639">
 <red-def:arch datatype="string" operation="pattern match">aarch64|ppc64le|s390x|x86_64</red-def:arch>
 <red-def:evr datatype="evr_string" operation="less than">0:1.3.15-7.module+el8.0.0+4084+cceb9f44</red-def:evr>
</red-def:rpminfo_state>
```
</details>

### tests
Представляет собой список тестов.

Тест - класс, устанавливающий соответствие между объектом и состояниями. 
Объект должен присутствовать всегда в единственном числе.
Состояния могут не присутствовать вовсе. Их максимальное количество не ограничено.

Результатом выполнения теста должен быть булеан. Алгоритм выполнения зависит от атрибутов теста и наличия состояний.

1. Получение целевых элементов из объекта;
2. Убедиться что условие `check_existence` (по умолчанию `at_least_one_exists`) выполняется;
3. Проверить состояния; в ходе проверки использовать атрибуты `check` (сколько целевых элементов должно пройти) и `state_operator` (сколько условий должно выполниться)

Получение false на любом этапе означает что тест результировал в false.

<details>
<summary>Пример test</summary>

```xml
<red-def:rpminfo_test check="at least one" comment="kpatch-patch-4_18_0-193_19_1 is signed with Red Hat redhatrelease2 key" id="oval:com.redhat.rhsa:tst:20204331035" version="637">
 <red-def:object object_ref="oval:com.redhat.rhsa:obj:20204331009"/>
 <red-def:state state_ref="oval:com.redhat.rhba:ste:20191992002"/>
</red-def:rpminfo_test>
```
</details>
