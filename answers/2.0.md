# Задача №2 Анализ уязвимости

| Поле                  | Значение        |
|-----------------------|-----------------|
| CVE                   | CVE-2026-125350 |
| Дата публикации       | 10.11.2026      |
| Срок устранения       | 24.11.2026      |
| Вендор                | Google          |
| Продукт               | Google Chromium |
| Компонент             | XML/XSLT        |
| Версия с исправлением | 157.0.8103.50   |

## Краткая справка
Уязвимость `CVE-2026-125350: Google Chromium Use-After-Free` была опубликована спустя 4 дня после анонимного отчета, 
полученного Google 06.11.2026.
Уязвимость позволяет атакующему удаленно выполнять код внутри песочницы Chromium с помощью HTML-страницы. 
Уязвимость затрагивает все основанные на Chromium продукты: Google Chrome, Microsoft Edge, Opera.
Google подтверждает наличие случаев эксплуатации уязвимости.

## Технический разбор
В своем отчете Google не раскрыл способы эксплуатации уязвимости, ожидая пока пользователи обновятся, однако подтвердил
существование эксплойтов. В связи с этим мы можем оценить механику уязвимости, исходя из известной нам информации.

Уязвимость основана на `CWE-416: Use after free`. Такие уязвимости возникают когда приложение продолжает использовать
указатель на участки памяти её освобождения (висячий указатель). Заполнив такие участки новой информацией, 
атакующий может добиться выполнения вредоносного кода на атакуемом устройстве, когда висячий указатель будет использован программой.
Однако такую уязвимость сложно эксплуатировать перебором. Поэтому в связке с ней часто используется атака на кучу `heap grooming`,
позволяющая контролировать, куда будет выполнена запись нужной атакующему информации.

В случае `CVE-2026-125350`, уязвимость присутствует в XML компоненте, отвечающем за отображение XML.
Это позволяет предположить, что эксплойт сводится к поиску xml-связанного действия (например обработка xml-тэга), 
логика обработки которого использует висячий указатель. 
После этого атакующий может создать страницу, при заходе на которую будет выполняться JS-скрипт, выполняющий heap grooming 
и тригерящий чтение из висячего указателя.

## Практическую опасность
Уязвимость приводит к RCE в случае отключенной песочницы с помощью флага `--no-sandbox`. В остальных случаях для полноценного
RCE требуется вторая уязвимость для выхода из песочницы (о ее существовании пока не известно).

Уязвимость затрагивает любой браузер на базе Chromium версии ниже `157.0.8103.50`. Это означает что другие браузеры должны
выпустить свои обновления безопасности, перед тем как уязвимость будет полностью устранена. Пример: Microsoft подтвердил
наличие уязвимости в Edge, но пока не выпустил патч. 

Google подтвердил наличие случаев эксплуатации, однако сами кейсы держатся в секрете. Эксплойт найти не удается. 
Если репозиторий с ним существовал, то он уже заблокирован по просьбе вендора.

Основываясь на характере уязвимости, можно выделить следующие сценарии атак:
* Целевой фишинг со ссылкой на подготовленную страницу;
* Watering hole

## Устранение и митигация
### Конфигурация браузера:
* Обязательно убедиться в отсутствии флага `--no-sandbox`. 
В обычном режиме для полноценной атаки требуется вторая уязвимость для выхода из песочницы. Если она отключена, атакующий
сразу получает полный контроль над устройством.
* Отключить JS для недоверенных доменов (`chrome://settings/content/javascript`). Т.к. эксплуатации уязвимости основывается на выполнении JavaScript, 
его частичное отключение позволит обезопасить устройства.
### Сетевые ограничения
* Ограничить доступ к недавно зарегистрированным доменам (например с помощью данных WHOIS);
* Карантин для писем со ссылками / вложениями;
### Правила для SIEM/EDR
* Chrome крашнулся после посещения недоверенного сайта;
* Chrome порождает консольные процессы: cmd, powershell, bash.
