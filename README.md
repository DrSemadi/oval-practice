## Краткое описание
Данный репозиторий содержит результаты выполнения второго этапа отбора. 
В данном `README` описывается скрипт `oval_parser.py`
Результаты выполнения других заданий находятся в папке `answers`

## Установка
1. Убедиться что установлен Python >= 3.10
2. Стянуть проект
3. Положить файл oval definitions в каталог с проектом

## Использование
1. Выполнить команду из ТЗ: `python oval_parser.py rhel-8.oval.xml`
2. Результат работы находится в одноименном `.json` файле.

Путь до входного файла может быть абсолютным или относительным от CWD.

Дополнительные аргументы можно посмотреть с помощью `--help`

### Описание аргументов
`-c, --count` - конвертировать первые N патчей (definitions); по умолчанию 5

`--id` - конвертировать патч по его id; можно указывать несколько раз

`-o, --output` - указать куда сохранить результат конвертации; как и исходный файл, может быть абсолютным или относительным от CWD

`--raw` - отключить конвертацию; файл будет сохранен в json, но без применения правил упрощения, с максимальным сохранением иерархии и атрибутов;

`--dnf` - преобразовать criteria в дизъюнктивную нормальную форму

`--no-format` - записать json в одну строку

`--naming-template` - задать шаблон id кастомных элементов, создаваемых конвертером в процессе упрощения; 
должен содержать поля для `str.format` - `{name}` и `{num}`, используются для генерации идентификатора;
шаблон по умолчанию: `oval-converter:{name}:{num}`

`--pdb` - дебаг-флаг, остановить выполнение скрипта после генерации до выхода из программы; позволяет в ручном режиме изучить
AST и протестировать конвертацию. Подробнее см. Примеры использования

## Принцип работы

Скрипт работает в 3 этапа: формирование AST, уточнение AST, разрешение зависимостей.

### Формирование AST
На данном этапе исходный файл парсится с помощью `xml.sax` и конвертируется в `AST`. В отличие от `ElementTree`, sax
не загружает весь xml в память, а парсит его постепенно, триггеря ивент на каждый открытый/закрытый тег.
Эти ивенты использует `src.parser.xml_parser.OVALParser`
для создания `AST` (Abstract Syntax Tree, Абстрактное Синтаксическое Дерево). Одной нодой дерева является один xml-тэг.
Дерево гетерогенное, поэтому каждому тегу соответствует свой класс ноды, однако на первом этапе таких классов мало.

### Уточнение AST
На первом этапе дерево неточное т.к. не все теги (ноды) можно идентифицировать по названию. 
Большинству из них присваивается дефолтный класс `ValueNode`, неспособный к специализированной логике.
Чтобы это исправить, на втором этапе делается проход по `AST` с помощью класса-визитера. Он посещает каждую ноду и 
переделывает ее в соответствии со своими инструкциями. Инструкции реализуются посредством `visit-методов`, 
явно указывающих в какой очередности должна обрабатываться сама нода и ее дети.

Также на этом этапе выполняется упрощение формата: из `definition` удаляется `metadata`, тесты, объекты и состояния уточняются 
до подклассов, а цепочка criteria-criterion разрешается в `DNF` (Disjunctive Normal Form).
См. [answers/1.3.md](answers/1.3.md)

### Разрешение зависимостей
На предыдущем этапе ноды-контейнеры `definitions`, `tests`, `objects` и `states` были уточнены до нод-индексов.
Такие ноды позволяют находить свои дочерние ноды при помощи индекса `id - child`. Это используется для разрешения зависимостей:
любая нода-ссылка обращается к соответствующему индексу и заменяется на хранящееся там значение. 
Если значение по какой-то причине не найдено, (часть файла была удалена) ссылка сохраняется на месте для сигнализирования проблемы.


Чтобы конвертировать дерево в `json`, в его корне вызывается метод-конвертер, 
который рекурсивно схлопывает дерево в набор вложенных словарей и списков. Каждая нода может задать собственный метод конвертации, 
что позволяет точно контролировать как именно будет отдавать информацию та или иная нода. Если такой метод не задается, используется формат по умолчанию (можно вызвать вручную флагом `--raw`)
